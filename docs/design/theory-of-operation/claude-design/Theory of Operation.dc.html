Theory of operation

Nightstand monitoring platform

One Raspberry Pi 5 is the system of record for one person’s physiology. It captures every night, judges continuously, sounds a klaxon when the pattern demands it, answers “what happened last night” every morning, and proves to itself that it still works.

How to read this sheet

The signal path is instrumented at fourteen test points, TP1 at the skin and TP14 at the bedside glass. Each point states what passes through it, what a healthy reading looks like, what the absence of a reading means, and which screen shows it. A fault is located by walking the register in order until a point’s healthy condition fails.

Three loops share this plumbing and serve different masters. The night path (TP1–TP12) serves the alarm. The morning path (TP6, TP13–TP14) serves understanding. The trust loop reads every point and serves the other two. Where they compete for the machine, the night path wins.

Three states, not two
MEASURED & FINE — quietest thing on any screen
MEASURED & BAD — solid, unmistakable
NOT MEASURED — hatched, and louder than fine

The invariant that outranks every other rule here: unknown never looks like healthy. Wherever the third state appears — a NULL in the store, a stale source on the panel, a gated sample in the detector — it is drawn heavier than the first.

TP1
Body surface
Polar H10 chest strap: beat-to-beat RR intervals, continuous — the only true HRV source. EMAY SleepO2: SpO₂ and pulse, ~1/s. A&D UA-651BLE cuff: on demand. AirSense 11 CPAP: one import per night (AHI, mask leak, pressure). HealthKit bridge: hourly push. Oura via cloud: daily. Journal entries and medication doses, entered by hand.
Every source reporting at its registered cadence. The hand-entered journal is the anchor: the physiology is context for it, not the reverse.
Strap off the body, or the oximeter dark, means no HRV and no SpO₂. The tier machine holds at can't assess. It does not clear.
Panel source list · cadence registry
TP2
Radio
One long-range BLE dongle, Sena UD100-G03. It is the only radio in the system.
Dongle enumerated; every expected peripheral connected; packet arrival matching each device’s advertised interval.
All BLE sources going dark in the same second is a radio fault, not a physiological event, and the machine says so in that language.
Admin console — technical alarm
TP3
Collector / decode
One collector per device protocol. Each emits rows already encoded in PostgreSQL binary COPY format — the wire format of the store is produced at the edge, not later.
Decoded row rate tracks the source cadence 1:1. No re-encoding stage exists downstream to go wrong.
Peripheral connected but no rows emitted isolates the fault to protocol decode — a code fault, not a hardware one.
Admin console · Health
TP4
Spool
Append-only, fsync’d to NVMe. This is the durability line: a sample survives a crash from the moment it is spooled, before any database is involved.
Spool depth near zero, write offsets monotonic, fsync latency inside its normal band.
A growing spool is a drain problem, not a data-loss problem. Nothing spooled is lost to a power cut.
Admin console — spool depth
TP5
Drain
Streams spool bytes straight into TimescaleDB. Because the bytes are already COPY-formatted, the drain parses nothing.
Cycle completes, committed offset advances, spool truncates behind it.
A stalled drain shows as backpressure at TP4 and stale freshness at TP6 — never as missing physiology.
Admin console — drain cycles
TP6
Store
TimescaleDB on PostgreSQL 16. Hypertable on NVMe, compressed after 7 days, raw dropped at 2 years.
Chunk written and queryable; compression job current; retention job current.
Gaps are stored and served as NULL. Nothing interpolates across missing physiology, and every reader renders NULL as not-measured.
Every readout, via TP13
TP7
Quality gate
Per source. First stage of the detection pipeline, which reads the live stream, not the stored table.
Sample admitted with a quality flag attached; the flag travels with it to TP8 and TP9.
A gated or artifact sample can never escalate a tier and can never clear one. It holds.
Admin console — gate rates
TP8
Severity scoring
Baseline-relative, against this person’s own rolling median. Population norms are never used, at any point on this sheet.
Score expressed as a departure from that baseline, carrying the baseline window it was computed against.
Too little history to hold a baseline is itself a not-measured state, not a benign one.
Dashboard — trends
TP9
Cross-sensor fusion
Combines the scored streams and weighs their agreement.
Two independent sources agreeing on a departure. Agreement is what buys the machine the right to escalate.
One source alone, or sources disagreeing, yields a candidate the tier machine may hold on but not fire from.
Admin console — fusion trace
TP10
Tier machine
Hysteretic, five tiers. The only component authorised to decide that a person is in trouble.
Tier stated with the evidence that set it and the time it entered that tier. Only observed primary evidence — SpO₂, respiration — moves it past watch in either direction.
No evidence at all is can't assess, which is a held state, not a quiet one.
Panel status light · console
TP11
Klaxon trigger
Entry into klaxon fires the whole channel stack at once, not in sequence.
Every channel dispatched in the same event, each reporting its own result independently.
A channel that reports nothing is presumed dead and is why the stack has more than one member.
Admin console — dispatch log
TP12
Siren current
The GPIO piezo siren senses its own current draw, so the machine learns whether it actually made a sound.
Current drawn during a fire or a scheduled self-test. This is the end of the night path: the audible world.
Commanded but no current means the loudest channel is dead — the highest-priority technical alarm in the system.
Admin console — self-test
TP13
Query daemon
Three verbs, and every reader on the sheet draws through them: Query (history), Health (liveness and freshness of every source and subsystem), Subscribe (live stream).
All three verbs answering, and every answer carrying the age of the observation behind it.
A dead daemon blinds every viewer and changes nothing about the alarm.
Dashboard · panel · phone
TP14
Bedside glass
800×480 panel; status light readable at 3 a.m. from three feet.
Panel showing the current tier and the age of each source.
Panel dark is a viewer fault. The alarm sounds identically with the panel unplugged.
The nightstand
II · TP10 in detail — the tier machine
clear
Observed, and within baseline. The quietest state on every screen.
can’t assess
No admissible primary evidence. Held, never cleared, and drawn louder than clear.
watch
A departure is scored. Nothing sounds. Only observed SpO₂ or respiration moves the machine past this line.
confirm
Fused agreement on CNS depression, sustained through hysteresis. Prompting channels only.
klaxon
Fires the entire channel stack. Designed to wake this person from the depression it just detected.

Hysteresis runs in both directions, which is the whole reason the machine is trustworthy: a tier that was earned by evidence can only be given up by evidence. Missing data holds the current tier. Artifact holds the current tier. Silence is never agreement.

III · The channel stack

Ordered by what each channel refuses to depend on, not by loudness. The stack is not a fallback chain — the klaxon fires all of it — because any one channel can be dead without notice.

GPIO piezo siren — a pin, a MOSFET, 12 V. No USB, no audio stack, no kernel sound path. Senses its own current draw (TP12).
Bed shaker on a relay. Depends on a coil and 12 V. Reaches a person who cannot hear.
USB DAC → amplifier → speaker. Depends on USB and the audio stack.
Zigbee devices. Depends on a mesh and its coordinator.
Push to phone. Depends on the network, a vendor service, and a charged handset.
Watch haptic. Depends on everything above it plus a worn, paired, charged watch.
IV · The latency budget

Radio packet to tier evaluation, end to end. Latency is part of how the machine works, so it carries a number: p99 under 2 seconds. Above 5 seconds is not slowness, it is a fault the system must surface as a technical alarm.

V · Morning path — who reads TP13, and for what
Bedside panel  TP14
Tier and source ages, legible from three feet in the dark. A viewer, never a dependency — the single most misunderstood line in the architecture.
Web dashboard
Last night as four synchronised lanes; trends against this person’s own rolling median, never population norms; system health.
Admin console
The operator’s room, technical alarms only. A dead oximeter is not a sick patient; the two kinds of alarm never share a voice, a channel, or a screen.
Phone
Three jobs, deliberately: HealthKit bridge in, journal in, viewer out. Nothing on the night path waits on it.
Clinical PDF
Built for an appointment: what was measured, what was not, and the age of each observation.
AI analysis jobs
Run under a monthly cost cap; produce reviewable text. Never silent edits, and never anything the tier machine consults.
VI · Trust loop — the machine watching itself
Hardware watchdog, 15 s. A hung host reboots itself rather than pretending to watch.
CPU governor pinned; undervoltage and thermal readouts surfaced as first-class technical alarms.
Nightly full backup plus WAL shipping, three retention tiers.
Scheduled restore into a scratch cluster — a backup that has never been restored is a hypothesis, not a backup.
“If this box died right now, what would I lose?” A standing answer, measured in minutes.
Alarm self-test on a schedule, verified at TP12 by current draw rather than by a return code.
Per-source cadence registry, so a silent sensor is distinguishable from a failing one.
Every status, everywhere, carries the age of the observation behind it. A number with no age is not a status.
Read the sheet in one line: the spool decides what survives, the tier machine decides what is true, the channel stack decides who finds out, and the trust loop decides whether any of the three can still be believed. Unknown never looks like healthy — if a change to this system would violate that, the change is wrong.
